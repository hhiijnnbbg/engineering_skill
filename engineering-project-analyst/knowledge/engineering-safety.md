# 工业软件安全规则

本 Skill 区别于普通 AI 的核心约束。所有 change-plan 必须逐条核对。

## 禁止修改层

以下层次默认禁止修改，除非用户明确要求：

```text
Camera SDK Layer     — 相机 SDK 封装层
Hardware Driver      — 硬件驱动相关
Database Core        — 数据库核心访问层
```

原因：这些层经过长期现场验证，修改风险远高于收益。确需变更时，优先在上层做适配。

## 稳定性要求

任何方案必须回答以下问题：

### 掉线

- 设备掉线时系统行为是什么？
- 重连后状态如何恢复？
- 掉线期间的数据是否丢失，丢失是否可接受？

### 异常恢复

- 进程异常退出后，未保存的数据怎么办？
- 文件（视频/记录）是否可能损坏，如何缩小损坏窗口？
- 重启后能否回到一致的状态？

### 资源释放

- 异常路径上资源是否仍会释放？（try-finally / Dispose）
- 长时间运行是否存在缓慢泄漏？（句柄、内存、文件句柄）

### 数据一致性

- 写入是否是原子的或有失败回滚？
- 多线程/异步下共享状态是否有保护？

## 方案红线

出现以下情况的方案直接否决或要求重做：

- 在 UI 线程执行 SDK 阻塞调用
- 修改禁止修改层且无用户明确授权
- 无异常恢复设计的长时运行任务
- 破坏现有状态机合法跳转路径
