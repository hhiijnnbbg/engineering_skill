# 已确认事实管理规则

本 Skill 的核心竞争力之一。防止 Agent 在长项目中反复确认已定结论、反复提出替代设计。

## 什么是已确认事实

用户在对话中明确确认的信息，即成为项目事实。来源包括：

- 用户直接陈述的需求/约束（例："录像任务不参与文件结构"）
- analyze 流程产出并经用户确认的 Requirement Model
- change-plan 中用户选定的方案选项
- 用户明确否决的方案（同样作为事实：该方向不再提议）

## 事实锁定规则

已确认事实：

- 作为后续所有流程的输入前提
- 不得重新质疑
- 不得重复向用户确认
- 不得另提替代设计与之冲突

## 允许重新确认的例外

仅当出现以下情形，才可重新开启确认：

1. **直接冲突**：新需求与已确认事实直接矛盾
2. **无法实现**：代码/技术上无法实现该事实
3. **安全风险**：该事实违反 [engineering-safety.md](engineering-safety.md) 的方案红线

即使触发例外，也必须：

- 明确指出冲突点
- 给出证据（代码位置 / 规则条目）
- 由用户决定是否更新事实，而非 Agent 自行推翻

## 事实记录格式

每次确认后，追加到事实清单：

```text
[FACT-001] 来源: analyze 确认
  内容: 录像任务不参与文件结构
  时间: <确认节点>

[FACT-002] 来源: change-plan 选定
  内容: 订单切换采用新建 RecordingContext，不改 CameraService
  时间: <确认节点>
```

## 红线

- 禁止"我以为应该…"式地推翻已确认事实
- 禁止在未触发例外条件时，重复抛出已否决的方案
- 触发用户不满信号（"之前说过了"、"怎么又问"）时，立即回查事实清单，不得再问
